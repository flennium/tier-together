# Architecture

Tier Together is one Ludicord application with a persistent React Activity shell and a single primary embed. The browser renders the board, handles local interaction state, creates optimistic move requests, and generates the final board image. It does not choose a Discord identity, room, host, or authoritative result. Pure functions in `lib/` describe board transitions, vote aggregation, and recap calculations, which keeps those rules testable without a browser or Discord connection.

The WebSocket route at `app/ws/board/socket.ts` is the authority for the active room. Ludicord authenticates the connection, supplies verified user and Activity context, and applies transport limits. The route combines the verified application and instance identifiers to isolate rooms, validates every event, enforces host-only actions through the board rules, remembers operation IDs for idempotency, and broadcasts a fresh snapshot after accepted changes. Rooms and custom item images live in memory, idle rooms expire, and reconnecting clients rejoin the current snapshot. This deliberately assumes one server process.

HTTP is limited to process health and the export handoff. The export POST is authenticated, accepts only a bounded PNG with the correct signature, and associates one short-lived file with the verified user. It returns a relative path so an incoming host header cannot choose the external destination. The tokenized GET is public only because Discord has to open it outside the Activity frame; its token is random, its response cannot be cached, and the content expires after five minutes. The legal pages are also public so Discord’s application listing can link to them, while the main product surface shows a Discord-only message when opened directly.

Ludicord owns OAuth, encrypted cookies, Discord proxy verification, Activity-instance verification, routing, and the WebSocket transport. Production host and origin boundaries are configured in `ludicord.config.mjs`. Railway starts the compiled Node server and checks `/api/health`; it should remain at one replica until room state and command serialization move to shared infrastructure.
