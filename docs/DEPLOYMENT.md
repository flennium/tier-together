# Production deployment

Tier Together deploys as a Node.js service, not as a static site. Connect the repository to Railway, let `railway.json` install from the lockfile and run the Ludicord build, then generate a public HTTPS domain. Store the Discord application credentials, session key, deployment mode, and exact allowed hostname in Railway’s secret settings. Never paste those values into source files, screenshots, build arguments, or documentation. Keep the service at one replica because active rooms are stored in process memory, and keep Railway’s health check pointed at `/api/health`.

In the Discord Developer Portal, enable the Activity, map the Activity route to the Railway domain, and keep the OAuth redirect URI exactly aligned with the Ludicord callback described by the installed framework documentation. Add the public `/terms` and `/privacy` URLs to the application information. Upload the artwork from `public/discord-assets/`, set the intended installation contexts, and grant only the scopes and permissions the current application uses. The Activity needs identity authorization and instance verification; it does not need broad message, member, moderation, or administrator permissions.

The public server-install link is `https://discord.com/oauth2/authorize?client_id=1556478676881776730&scope=bot%20applications.commands&permissions=0&integration_type=0`. It requests the bot and application-command scopes with no bot permission bits. Keep Guild Install and Public Bot enabled in the Developer Portal for this link to work for users outside the development team.

Before promotion, run `npm ci`, `npm test`, `npx ludicord routes`, `npx ludicord lint`, `npx tsc --noEmit`, `npm audit --omit=dev`, and `npm run build` from a clean checkout. Confirm that the build’s secret scan passes and that no ignored environment file is staged. After Railway deploys, check the health route and open the public root to verify the Discord-only page. Then launch from Discord and complete both ranking modes with two clients, refresh one client, test host transfer, add a temporary image, use keyboard and controller navigation, resize the Activity to its narrow layout, and export a PNG through the external browser handoff.

Watch the first real sessions for process restarts, memory growth, repeated authorization failures, WebSocket reconnect loops, rejected commands, and export errors. A restart clearing rooms is expected in this release; participants should be told when a deployment interrupts an active session. Roll back the deployment if authentication, room isolation, or command authorization behaves unexpectedly. Rotate a credential immediately if it appears outside the secret store, even if Git history is later rewritten.
